## 1. Resumen Ejecutivo

La versión 1.0 marca el primer release estable y completo del proyecto **Mis Tarjetas Pro**. Representa la culminación de la migración desde una arquitectura monolítica PHP/HTML hacia una SPA moderna con Vue 3 + Firebase, incluyendo la corrección de múltiples defectos críticos y la implementación completa de capacidades PWA.

## 2. Corrección PWA

### Problema
La aplicación no cumplía con los requisitos mínimos de instalación PWA. Faltaban iconos físicos, las rutas eran absolutas y el manifest no tenía las propiedades requeridas.

### Solución implementada

| Aspecto | Detalle |
|---------|---------|
| **Plugin** | `vite-plugin-pwa` v1.3.0 configurado en `vite.config.js` |
| **Registro SW** | `registerSW({ immediate: true })` en `src/main.js` |
| **Estrategia** | `registerType: 'autoUpdate'` — actualizaciones silenciosas |
| **Cacheo** | Workbox con `globPatterns: ['**/*.{js,css,html,ico,png,svg}']` |
| **Iconos** | `public/img/pwa-192x192.png` y `public/img/pwa-512x512.png` creados |
| **Purpose** | `"any maskable"` en ambos iconos para máxima compatibilidad |
| **Rutas** | Corregidas de absolutas (`/img/pwa.png`) a relativas (`img/pwa.png`) |

### Configuración del Manifest

```js
manifest: {
  name: 'Mis Tarjetas Pro',
  short_name: 'Tarjetas',
  description: 'Gestor avanzado de tarjetas de crédito',
  theme_color: '#f8fafc',
  display: 'standalone',
  // start_url y scope generados automáticamente por vite-plugin-pwa
  // respetando base: '/Tarjetas/'
}
```

### Compatibilidad verificada

| Plataforma | Estado |
|------------|--------|
| Chrome Desktop | ✅ Instalable |
| Chrome Android | ✅ Instalable (manual desde menú) |
| Samsung Internet | ✅ Badge PWA detectado automáticamente |
| Edge Desktop | ✅ Instalable |
| Firefox | ⚠️ Sin soporte PWA nativo (comportamiento esperado) |

### Auto-actualización
Cuando se despliega un nuevo build en GitHub Pages, el Service Worker detecta la actualización silenciosamente, descarga los nuevos assets y reemplaza la caché. Los usuarios reciben la versión actualizada sin necesidad de reinstalar la PWA.

## 3. Compatibilidad GitHub Pages

### Problema original
Al recargar la página o acceder directamente a rutas como `/Tarjetas/login`, GitHub Pages devolvía **404 File Not Found**. Esto ocurría porque GitHub Pages es un servidor estático puro que no soporta redirecciones server-side a `index.html`.

### Efectos del problema
- Recargas de página rotas
- Validaciones de Service Worker fallidas
- Evaluaciones de instalación PWA inhabilitadas en Chrome
- Experiencia de usuario completamente rota

### Solución: migración de historial

```js
// ANTES (roto en GitHub Pages):
createWebHistory()

// DESPUÉS (compatible):
createWebHashHistory()
```

### Impacto
Las rutas ahora usan el formato hash (`/Tarjetas/#/login`). GitHub Pages siempre sirve `/Tarjetas/index.html` independientemente de la ruta solicitada. El enrutamiento ocurre en el lado del cliente al leer el fragmento hash.

### Rutas finales

| Ruta | Vista |
|------|-------|
| `/#/` | Dashboard |
| `/#/compras` | Módulo de Compras |
| `/#/tarjetas` | Gestión de Tarjetas |
| `/#/proyecciones` | Proyecciones Financieras |
| `/#/configuracion` | Configuración |
| `/#/login` | Inicio de Sesión |
| `/#/registro` | Registro |

> **Regla crítica:** NUNCA volver a `createWebHistory()`. Rompe permanentemente GitHub Pages.

## 4. Seguridad Firebase

### Problema
El archivo `.env` con credenciales Firebase estaba inicialmente incluido en el tracking de Git, exponiendo las credenciales en el repositorio público.

### Solución implementada

#### Arquitectura de archivos de entorno

| Archivo | ¿En GitHub? | Propósito |
|---------|-------------|-----------|
| `.env` | ❌ NUNCA | Credenciales reales de Firebase (solo local) |
| `.env.example` | ✅ Sí | Plantilla sin valores para referencia |
| `.gitignore` | ✅ Sí | Regla de exclusión para `.env`, `.env.local`, `.env.*.local` |

#### GitHub Actions Secrets
Se configuraron **6 GitHub Repository Secrets** para inyectar las variables en el pipeline CI/CD:

```yaml
env:
  VITE_FIREBASE_API_KEY: ${{ secrets.VITE_FIREBASE_API_KEY }}
  VITE_FIREBASE_AUTH_DOMAIN: ${{ secrets.VITE_FIREBASE_AUTH_DOMAIN }}
  VITE_FIREBASE_PROJECT_ID: ${{ secrets.VITE_FIREBASE_PROJECT_ID }}
  VITE_FIREBASE_STORAGE_BUCKET: ${{ secrets.VITE_FIREBASE_STORAGE_BUCKET }}
  VITE_FIREBASE_MESSAGING_SENDER_ID: ${{ secrets.VITE_FIREBASE_MESSAGING_SENDER_ID }}
  VITE_FIREBASE_APP_ID: ${{ secrets.VITE_FIREBASE_APP_ID }}
```

#### Mecanismo Vite
Vite usa `import.meta.env.VITE_*` para exponer variables al cliente. Durante `npm run build`, cada referencia se reemplaza estáticamente por su valor literal. Si la variable no existe, se inyecta `undefined`, provocando crash silencioso de Firebase.

## 5. Corrección de Pantalla Blanca

### Diagnóstico completo

| Fase | Evento |
|------|--------|
| 1. Acción | Se ejecutó `git rm --cached .env` para proteger credenciales |
| 2. Efecto | `.env` eliminado del repositorio remoto |
| 3. Build | GitHub Actions clona repo → no encuentra `.env` → variables = `undefined` |
| 4. Firebase | `initializeApp()` recibe `apiKey: undefined` → crash silencioso |
| 5. Auth | `onAuthStateChanged` nunca resuelve |
| 6. Router | Guard redirige al login infinitamente |
| 7. UI | **Pantalla blanca completa** en producción |

### Solución
1. Configuración de **GitHub Repository Secrets** con las 6 variables Firebase
2. Modificación de `.github/workflows/deploy.yml` para inyectarlas como `env:`
3. Rebuild con commit vacío → deploy exitoso

### Lección aprendida
Siempre que se elimine un archivo del tracking de Git que sea necesario para el build, verificar que exista una fuente alternativa para el pipeline CI/CD.

## 9. Estructura de Versionado

A partir de esta versión, los cambios significativos del proyecto se documentarán en archivos separados dentro de `docs/versions/`.

### Convención de archivos

```
docs/versions/
├── v1.0.md      ← Este archivo (release inicial)
├── v1.1.md      ← Próxima versión menor
├── v1.2.md
├── v2.0.md      ← Cambio mayor de arquitectura
└── ...
```

### Cuándo crear una nueva versión

| Tipo de cambio | Ejemplo | Versión |
|---------------|---------|---------|
| Corrección menor / hotfix | Fix de bug visual | No requiere doc |
| Nueva funcionalidad | Módulo de exportación PDF | v1.x |
| Cambio de componentes | Refactor de un módulo | v1.x |
| Cambio arquitectónico mayor | Migración de estado, nueva DB | v2.0 |
| Breaking changes | Reestructura de Firestore | v2.0 |

### Contenido mínimo por versión

Cada archivo de versión debe incluir:
1. Fecha y tipo de release
2. Resumen de cambios
3. Archivos creados/modificados
4. Impacto en compatibilidad
5. Estado de verificación (build, PWA, deploy)

### Referencia base

El archivo `docs/contexto_completo_proyecto.md` permanece como documentación arquitectónica base y contexto general. No debe modificarse con frecuencia — solo para actualizar la estructura del proyecto si cambia significativamente.

## 12. Actualización de Iconos PWA (v1.0.1)

**Fecha:** Mayo 2026

### Cambio realizado
Se actualizaron los iconos instalables de la PWA usando una nueva imagen master de alta resolución (4096x4096) con diseño profesional de tarjetas de crédito apiladas.

### Assets generados

| Archivo | Tamaño | Propósito |
|---------|--------|-----------|
| `public/img/pwa-192x192-v2.png` | 192×192 px | Launcher icon (Android/Desktop) y Favicon |
| `public/img/pwa-512x512-v2.png` | 512×512 px | Splash screen, acceso directo, alta resolución |
| `public/img/apple-touch-icon.png` | 180×180 px | iOS Add to Home Screen (Acceso directo) |

### Configuración manifest

```js
icons: [
  { src: 'img/pwa-192x192-v2.png', sizes: '192x192', type: 'image/png', purpose: 'any maskable' },
  { src: 'img/pwa-512x512-v2.png', sizes: '512x512', type: 'image/png', purpose: 'any maskable' }
]
```

### Decisiones técnicas
- **Sufijo `-v2`:** Fuerza la actualización de caché en dispositivos que ya tienen la PWA instalada. El Service Worker detecta los nuevos assets y reemplaza la versión anterior.
- **`purpose: 'any maskable'`:** Garantiza compatibilidad tanto con iconos adaptativos de Android (safe zone circular) como con iconos estándar de escritorio.
- **Rutas relativas:** Se mantienen sin `/` inicial para compatibilidad con `base: '/Tarjetas/'`.
- **Old icons preservados:** `pwa-192x192.png` y `pwa-512x512.png` se conservan como respaldo histórico.

- ✅ Manifest incluye nuevas rutas
- ✅ Iconos accesibles en `dist/img/`
